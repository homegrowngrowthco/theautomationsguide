## Verdict up front

**One real, material problem found and fixed same-day: Google had not re-downloaded the sitemap in 58 days.** GSC's registered `sitemap-index.xml` showed `lastDownloaded: 2026-06-22` and only **94 submitted URLs** against the site's current 217. Since late June, Google has discovered new posts only by crawling internal links, which is consistent with the slow indexing of everything shipped since. Root-cause contributor: the sitemap carried **zero `lastmod` dates**, so Google had no change signal and no reason to re-read it.

Everything else checked is healthy. This was not a penalty, a noindex leak, or a crawl block. The strategic constraint (zero independent referring domains, confirmed today by the GSC links export: 27 linking pages, all from Ian's own homegrowngrowth.co + a self-created Crunchbase profile) remains the dominant visibility limiter — a technically perfect site with no inbound links still sits at position ~37.

## Findings

### F-1 (HIGH, FIXED `633b97b`): sitemap stale in GSC, 58 days
- Measured via Search Console API `sitemaps.list`: `lastDownloaded 2026-06-22T19:24Z`, submitted=94, current site=217 URLs.
- Fix shipped: real `lastmod` on all 106 blog URLs (`updatedDate || pubDate` from frontmatter, quote-agnostic + CRLF-aware parse). Static/hub pages deliberately carry NO lastmod — stamping build-time on unchanged pages would poison the signal.
- **Remaining manual step (@ian): resubmit `sitemap-index.xml` in GSC UI** (Sitemaps → enter → Submit). The API token is webmasters.readonly, so this can't be scripted here.
- Re-check ~8/26: `sitemaps.list` should show a fresh lastDownloaded and ~217 submitted.

### F-2 (info): live sitemap itself was NEVER stale
The deployed `sitemap-0.xml` is regenerated every build and contained same-day URLs (verified: hubs shipped 8/19 present within minutes of deploy). "Sitemap seems old" was GSC's stale *read* of it, not a generation bug.

### F-3 (clean): no crawl/index blockers
- robots.txt 200, allows all + explicitly allows AI crawlers (GPTBot etc.).
- No noindex leaks on sampled blog/hub/home/blog-index pages; NOINDEX_PATHS correctly excluded from sitemap.
- Canonicals correct (trailing-slash form), www→apex and http→https both 301.
- qa:seo gate: PASS, 0 hard issues. 51 advisory warnings, dominated by short `<title>`s on `/tools/` hub pages (~40 chars) and 1 description >165 chars — cosmetic, not blockers.

### F-4 (structural, known): thin hubs + zero authority are the real ceiling
- 13+ `/tools/` hubs remain unknown-to-Google (8/12 sweep) and IndexNow resubmission demonstrably does not rescue them; they need prose + inbound links. The 6 hubs shipped today enter the same pool (each has only the /tools/ index linking in).

## Addendum (same day, after Ian's resubmit): accountability sweep

**Resolution confirmed by API, not UI:** after Ian resubmitted, `sitemaps.list` shows `lastDownloaded 2026-08-19T20:02Z` with **217 of 217 URLs submitted**. The UI's lingering "94" was the child-sitemap row lagging; Google took the full re-read same-day. The lastmod fix + resubmit closed F-1.

**Root-cause accounting — what actually failed and why it went unseen:**
1. The sitemap integration shipped without `lastmod` from day one and two prior audits (7/13 SEO, 8/04 growth) checked indexation OUTCOMES but never the PIPE (GSC's lastDownloaded). A monitoring gap, not a one-off: the 5/22 decision to skip the Google Indexing API rested on the assumption "Google reads the sitemap", and no check ever guarded that assumption.
2. Fixed structurally, not just once: new weekly `seo-freshness` GHA fails loudly if Google's sitemap read is >14 days old or covers <80% of live URLs — and fails EQUALLY LOUDLY while its `GSC_TOKEN_JSON` secret is missing, so a blind watchdog can't pass as a healthy one.

**What the sweep verified working (with evidence, not assumption):**
- Per-post IndexNow submission: automated on every PR merge, verified firing today (execution 21962, HTTP 200). Google offers no equivalent ping since 2023; per-post Google push = the built-but-disabled Indexing API branch (decision now in TODO).
- GA4 tag present on prod; JSON-LD emitting (BlogPosting/FAQPage/Breadcrumb/Organization) on posts.
- Publish-status workflow: 100% success across recent executions, two per day (engine PR + merge).

**Additional drift found:** PR + Backlink Monitor n8n workflow is INACTIVE while CLAUDE.md listed it live (doc corrected; triage in TODO). GSC_TOKEN_JSON was referenced as "pending, see TODO" in CLAUDE.md but the TODO item had vanished without the secret being added (re-added @high).

**Scope correction for the record:** the zero-referring-domains problem is independent of the sitemap. A sitemap governs how Google discovers OUR pages; referring domains are other sites choosing to link to us, which no sitemap influences. Both are real; only one was a technical failure.
