# SEO Audit — theautomationsguide.com — 2026-07-13

Full-site audit (no URL scope). Production audited. Previous: [AUDIT-SEO-2026-07-07.md](AUDIT-SEO-2026-07-07.md).

## Verdict

Technically the site remains in excellent shape, and the July remediations demonstrably worked: indexation is now **140 of 145 URLs (96.6%)**, em/en-dash titles went **51 to 0**, and long titles went **108 to 34**.

But this audit surfaced **one live revenue leak** that the previous audit's toolchain could not see: `/go/quickmail/` **404s on production**, a broken affiliate CTA in the 2026-07-12 cold-email-infra post. `qa:seo` (the audit's on-page scanner) does not check `/go/` registry integrity — only `lint-content --all` does, and CI lints only the *changed* post. This is the same class as the S40/S41 C-1 finding.

Beyond that, two structural things. First, **16 of 67 tool hubs have no in-body inbound link, and that number regrows on its own**: auto-register mints a new tool's hub during CI *after* the draft was written, so a new hub can never appear in the slug list fed to the very post that introduces it. Every newly covered tool is born orphaned. Second, the blog-post mobile LCP finding (2.7s) should be **closed, not fixed** — the measurement now shows zero render-blocking resources and clean `font-display`, which exhausts the fix hypothesis the last audit recommended. Chasing it further is wasted effort.

That hypothesis is now **disproven by measurement**: `render-blocking-insight` reports **zero** blocking resources (the S59 CSS inlining removed the last one) and `font-display-insight` is **clean**. The LCP breakdown is TTFB 212ms + **element render delay 1210ms**, and the LCP element is a *text* node (`p.post-tldr-text`), so there is no image to preload and no font to unblock. The remaining delay is main-thread parse/render under Lighthouse's 4x simulated CPU throttle. There is no network-path lever left. **CrUX field data is the arbiter** (same conclusion as the S39 font work and the S59 CSS work — this is now the third time this loop has run). Recommend: stop investing, and only revisit if CrUX shows real-user LCP regressing once traffic clears the reporting threshold.

## Resolution (all fixed in the same session — PR `fix/orphan-hub-mesh`)

1. **`/go/quickmail/` 404 (Critical) — FIXED.** Registered `quickmail` in [src/data/affiliate-links.ts](src/data/affiliate-links.ts) as a `no-program` entry with `homepageFallback: 'https://quickmail.com/'` (the S50 mailchimp pattern). Homepage content-validated before use (real QuickMail cold-email site, not a soft-404; `quickmail.io` 301s to the apex). `/go/quickmail/` now builds and redirects with UTM. `lint-content --all`: **1 hard to 0 hard**.
2. **Orphan-hub FLOW (Medium) — FIXED at the source.** The auto-register CI step in [.github/workflows/qa-content-pr.yml](.github/workflows/qa-content-pr.yml) now runs `internal-link-mesh.mjs --post "$POST" --orphans-only --no-llm --write` immediately after minting the hub, so the introducing post links its own new hub. `--no-llm` means the CI path is **deterministic and key-free** — it can do nothing but wrap the tool's own name in prose that already exists — and the lint gate then proves the link resolves. The mesh changes ride the existing `[auto-register]` commit, so `auto-merge-content.yml`'s trailing-bot-commit regex (`^\[(auto-register|qa-fix-\d+)\]`) keeps working untouched.
3. **Orphan-hub STOCK (Medium) — FIXED.** Ran the mesh in `--orphans-only` mode: **9 links added across 6 posts**, orphans **16 to 8**. Every added link was reviewed by hand.
4. **Census substring bug — FIXED.** New `linksToHub()` requires the slug be followed by a non-slug character, so `/tools/surfer/` no longer masks orphan `surfe`.
5. **4 slashless `/tools/` links — FIXED.** All internal `/tools/` links now use the canonical trailing-slash form (zero remaining).
6. **Ambiguity guard relaxed where it is provably safe.** `Warmly` sits in the `AMBIGUOUS` set (to stop "warmly" the adverb being linked), which blocked the fallback on a post *titled* "RB2B vs Warmly vs Vector vs Factors". The fallback now permits an ambiguous alias **only when the tool is named in the post title**, where the word is unambiguously the product.

### The 8 remaining orphans are NOT fixable by linking, and that is correct

Seven (`motion`, `trigify`, `fullenrich`, `surfe`, `leadmagic`, `bettercontact`, `circleback`) are **LP-only hubs with no article written about them** — there is no prose anywhere to link from. They need *content*, not a mesh run, and they remain crawlable via the `/tools` A-Z index (the S26 fix). The eighth, `factors-ai`, is discussed in one post but **every** occurrence of its name is already inside an existing `[Factors.ai](/go/factors-ai/)` link or inside component data, so there is no free prose anchor; forcing one would mean rewriting prose, which this tool deliberately never does.
