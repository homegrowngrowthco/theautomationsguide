Most teams running [Close](/go/close/) alongside [HubSpot](/go/hubspot/) hit the same wall: deals move in Close, sequences live in HubSpot, and nothing talks to each other without someone manually copying contact records or firing off a Zap that costs more per task than it should. This tutorial walks through the exact [n8n](/go/n8n/) workflow I'd build to solve that, using Close webhooks, n8n's HTTP nodes, and the HubSpot Sequences API to create a loop that fires automatically when a deal stage changes.

## Why This Integration Is Worth Building

Close is a serious sales CRM. Its built-in calling, email, and pipeline views make it genuinely good for outbound-heavy teams. But most marketing and nurture infrastructure lives in HubSpot: sequences, contact scoring, lifecycle stages. The two tools serve different masters, and that gap creates real operational drag.

The usual answer is Zapier. Don't bother. Per-task pricing adds up fast once you're firing on every deal stage change across a busy pipeline. [n8n](/tools/n8n/) is the better move: self-hosted means no task tax, and the workflow canvas gives you the conditional logic you actually need (upsert a contact if they don't exist yet, skip enrollment if they're already in a sequence).

Per the [n8n HubSpot node docs](https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.hubspot/), HubSpot's node supports contact create, update, search, and sequence enrollment natively. Close's side is handled via webhook plus an HTTP Request node against the [Close REST API](https://developer.close.com/).

## The Workflow You're Building

The end state is a five-node n8n workflow. A Close deal moves to a specific stage (say, "Demo Booked"). Close fires a webhook. n8n receives it, extracts the contact's email, checks whether that contact exists in HubSpot, creates or updates the record, then enrolls them in the right HubSpot sequence based on the deal stage. No manual steps, no Zapier task counter ticking up.

The conditional branch in the middle is what makes this useful. Different deal stages map to different sequences. A demo booked stage might enroll into a pre-demo prep sequence, while a proposal sent stage hits a closing sequence. You build that logic once in n8n using IF nodes and it runs without intervention.

I'd argue most teams underestimate how much value lives in that branch. A single IF node replacing what would otherwise be manual rep judgment is the whole point.

## The Gotcha You Will Hit

The most common failure point in this workflow is the sequence enrollment step. HubSpot's Sequences API will reject the call if the contact does not have a valid email, if the sequence is paused, or if the enrolling user does not have a Sales Hub seat. Per the [HubSpot Sequences API docs](https://developers.hubspot.com/docs/api/crm/sequences), the n8n HubSpot node does not surface a clean error for the seat issue specifically.

<SideBySide>
  <Fragment slot="left">
    **The trap:** You wire everything up, the contact upsert works, but sequence enrollment silently fails with a 403. You check the API key and it looks fine. The real issue is that HubSpot's Sequences API requires the enrolling user (the email in the `userId` field) to hold an active Sales Hub Professional or Enterprise seat. A free or Marketing-only HubSpot user will fail every time, no matter how correct the rest of the payload is.
  </Fragment>
  <Fragment slot="right">
    ```json
    // Correct HubSpot Sequences enrollment payload
    {
      "sequenceId": "12345678",
      "contactId": "987654321",
      "startingStepOrder": 0,
      "enrolledFrom": "CRM",
      "userId": 112233
    }

    // userId must be a Sales Hub seat holder
    // Get your userId from:
    // GET https://api.hubapi.com/crm/v3/owners/
    // Match by email, use the numeric id field
    ```
  </Fragment>
</SideBySide>

The second gotcha: a contact already enrolled in a sequence returns a 409 Conflict. My read is you should add an error branch in n8n that catches 409s and logs them to a Slack channel or Google Sheet rather than letting the workflow fail silently. Build that from day one, not after your first missed enrollment.

Most RevOps teams over-engineer this by trying to keep Close and HubSpot in perfect two-way sync. The only data worth pushing from Close to HubSpot is deal stage and contact identity. Everything else (activities, call logs, notes) creates mapping headaches that outweigh the value. Sync the minimum, trigger the sequence, and let each tool do what it does best.
</MyTake>

## Putting It Together

The Close-to-HubSpot sync via [n8n](/tools/n8n/) is one of the cleaner integration recipes in the RevOps toolkit because the data model is simple: one deal stage change, one contact upsert, one sequence enrollment. The five-node workflow above handles the full loop. Wire up your Close webhook, grab your HubSpot Sales Hub owner ID from the [owners endpoint](https://developers.hubspot.com/docs/api/crm/sequences), map your stage names to sequence IDs, and the whole thing runs without supervision. The usual failure points (sequence enrollment 403s and 409s) are predictable and fixable at build time if you add error branches from the start.
